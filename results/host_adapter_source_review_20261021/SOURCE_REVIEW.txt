K(E)*count traceback records and a tail origin after C_effective(E)*workers
arena records. It enqueues results[count] and that tail on the SAME supplied
stream, then returns. CUDA_CHECK_ERR (cuda_utils.cuh:28-35) checks the last
CUDA error and exits on error; it is not a completion synchronization.
The entire archive has one full helper definition, one declaration and one
direct full caller, plus the analogous three distance-helper occurrences.

Full-CIGAR normal path in align.cu:
* 247 waits for stream1 H2D before packing; 259 waits for stream2 packing.
* 262-278 launches the current alignment on stream2.
* 284-296 synchronously consumes the PREVIOUS host result/tail while that
  current GPU batch runs. This helper finishes rescue AND normal RLE.
* 376-383 enqueues the CURRENT result/tail copy on stream2 after that reader
  has returned. It cannot overwrite the previous reader on this normal path.
* 431 waits for stream2, which orders the current kernel and BOTH copies.

* 438-450 consumes the final batch after the loop's last stream2 wait.

3. Error/alternate-path qualifications
The next-input size/bounds guards at align.cu:394/400 can break after copy-out
was enqueued but before 431. The analogous distance guards are 847/853 before
884. With valid immutable prepared metadata, the prior maximum-size audit and
buffer invariants are intended to make those guards unreachable. If one is
taken, normal final consumption must not be assumed safe merely from the usual
loop ordering. No such error was demonstrated in the measured R2 runs here.
Also, stream synchronize return values are not explicitly checked at those
source calls. An adapter must check its completion status and fail without
publishing READY or consuming incomplete data. Error logging is not completion.

The first loop copies uninitialized from/to/count into previous-batch locals
before the batch>0 guard. Their guarded consumers are unused at batch0. Record
this source initialization caveat; do not infer a measured effect. Initialize
the new adapter's job/loop state in a shared change for both candidate modes.
Do not use stream destruction or ordinary output teardown as a readiness signal.

alignment_result_t=20, alignment=4, offsets finished0/distance4/backtrace8/

K(16384)=2048. The source, CPU result and earlier conditional 20/8-byte model
agree. This was a CPU compiler with mock annotations, not nvcc or CUDA runtime.

Pinned payload for Q full-capacity slots is Q*B*(20+8*K(E)). For E16384,
B512: one slot 8,398,848 bytes, four 33,595,392, extra over one 25,196,544.
The last partial batch copies count rather than B entries; allocated capacity
may remain B. Queue/control structs, stacks, synchronization, allocator/pinned
overhead, global outputs and four BiWFA workspaces are not included in that
payload number. Complete host peak and native ABI/allocation receipts remain
required. No equivalent increase of GPU arena capacity is implied.

C_effective controls the DEVICE tail origin, not K(E). Allocation, launch and
copy agree on C_effective*workers followed by the result tail. Preserve E,
workers, environment capacity and stride throughout a request; do not recompute
them from a slot index or change the capacity environment during asynchronous
jobs. CPU RLE uses per-pair offset K*(i-from), independent of the worker arena.
